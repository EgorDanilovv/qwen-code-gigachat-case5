# Применение правок к файлам (Edit Format / SEARCH & REPLACE)

**Модель:** GigaChat-2-Max  
**Прокси:** gpt2giga v0.2.2a1  
**Клиент:** Qwen Code v0.19.6  
**Дата тестирования:** 2026-07-12

---

## Тестовое окружение

Для проверки механизмов автоматического редактирования файлов был создан тестовый файл `test.js`.

**Исходный код файла `test.js` (до начала тестирования):**

```javascript
// Тестовый файл для проверки автозамены
function calc(a, b) {
    return a + b;
}

function greet(name) {
    console.log("Hello, " + name);
}

module.exports = { calc, greet };
```

## Сценарий 1: Точечное переименование функции - Не работает

**Запрос:** "@test.js Переименуй функцию calc в calculate. Заменяй только те строки, которые нужно изменить, не трогай весь файл целиком."

| Параметр | Значение |
|----------|----------|
| Статус | ❌ Не работает |
| Инструмент | `edit` (SEARCH/REPLACE) |
| Авто-применение | ❌ нет (файл не изменен) |
| Ошибки парсинга | `0 occurrences found for old_string` |

**Проблемы:**
1. **Жадный контекст:** Модель игнорирует инструкцию "не трогай весь файл" и помещает в параметр `old_string` всё содержимое файла целиком.
2. **Фантомные символы:** Добавляет невидимые переносы строк `\n` в начало и конец JSON-строки `old_string`.
3. Из-за добавленных `\n` парсер Qwen Code (работающий по принципу строгого совпадения - strict string matching) не находит текст в исходном файле и прерывает операцию.

**Запрос:** "@test.js Измени логику внутри calculate, чтобы она возвращала a * b вместо a + b. В поле old_string передай СТРОГО ОДНУ строчку: ' return a + b;'. Не копируй весь файл!"

| Статус | ✅ Работает (с жестким промптом) |
| Инструмент | `edit` |
| Авто-применение | ✅ да (Qwen применил diff) |

- Передан идеальный, минимальный блок `old_string`.
- Парсер Qwen Code успешно нашел строку, выдал diff-меню на подтверждение и автоматически изменил локальный файл.
- Использование одинарных кавычек (`'`) в сгенерированном коде предотвратило ошибки экранирования JSON.

## Сценарий 3: Переписывание блока кода (Arrow function) - Не работает

**Запрос:** "@test.js Преобразуй функцию greet в стрелочную функцию и заставь её выводить в консоль "Hello, " + name. Используй инструмент edit точечно."

| Параметр | Значение |
|----------|----------|
| Статус | ❌ Не работает |
| Инструмент | `edit` |
| Авто-применение | ❌ нет |
| Ошибки парсинга | `0 occurrences found for old_string` |

**Проблемы:**
1. **Баг экранирования:** Наличие двойных кавычек в требуемом коде (`"Hello, "`) заставило модель сгенерировать невалидный JSON с избыточным экранированием (`\\\"Hello, \\\"`). Qwen искал эти лишние слэши в файле и предсказуемо выдал ошибку.
2. Модель снова захватила весь файл в `old_string`, проигнорировав слово "точечно".
3. **Галлюцинация:** Получив от встроенного инструмента ошибку `Failed to edit`, модель проигнорировала её и выдала пользователю ложное сообщение об успешном выполнении задачи.

## Сценарий 4: Удаление кода - Критический сбой

**Запрос 1:** "@test.js Удали функцию greet... КАТЕГОРИЧЕСКИ ЗАПРЕЩАЮ включать функцию calculate в old_string!"
**Запрос 2 (сразу после ошибки):** "read the updated test.js"

| Параметр | Значение |
|----------|----------|
| Статус | ❌ Критический сбой (Agentic Loop) |
| Инструменты | `edit` / `read_file` |
| Авто-применение | ❌ нет |
| Выход из ошибки | Требуется Ctrl+C |

**Проблемы:**
1. **Instruction Override:** Модель полностью проигнорировала капслок и прямой запрет на включение функции `calculate`. Внутренние паттерны генерации LLM перебили пользовательский системный промпт.
2. **Agentic Death Loop:** При попытке заставить агента перепроверить файл (команда на чтение `read_file`), модель проигнорировала новую команду. Вместо этого она ушла в бесконечный цикл, раз за разом вызывая сломанный инструмент `edit` с абсолютно идентичным, ошибочным JSON.
3. Модель не способна к самокоррекции. Цикл был прерван только ручным вмешательством.

## Итоговая таблица для общего отчёта

| Функция | Статус | Описание проблемы | Обходное решение |
|---------|--------|-------------------|------------------|
| Точечное редактирование | ❌ Не работает | Жадный контекст, добавление фантомных `\n` ломает парсер Qwen. | В промпте жестко указывать СТРОГО ОДНУ строчку для `old_string`. |
| Баг экранирования | ❌ Не работает | Двойные кавычки в коде экранируются тройными слэшами (`\\\"`) в JSON. | Использовать одинарные кавычки (`'`) в промптах/коде. |
| Удаление блоков кода | ❌ Не работает | Модель игнорирует запреты на включение лишнего кода в контекст. | Просить модель полностью перезаписать файл (`write_file`). |
| Самокоррекция агента | ❌ Сбой | При ошибке формата уходит в бесконечный цикл (Agentic Loop). | Прерывать процесс вручную (Ctrl+C), очищать контекст (`/clear`). |

## Общие выводы

**Сильные стороны GigaChat-2-Max:**
- Модель генерирует синтаксически верный целевой код для замены.
- При точечном, жестком ограничении контекста (prompt engineering) механизм применения правок на локальном диске срабатывает успешно.

**Слабые стороны GigaChat-2-Max:**
- **Несовместимость форматов:** Модель не умеет работать со строгим парсингом `edit`. Лишние переносы строк и баг с `\\\"` полностью ломают автоматизацию.
- **Отсутствие самокоррекции:** Склонность к бесконечным циклам (Agentic Loop) делает оставление агента "без присмотра" невозможным.
- **Галлюцинации:** Модель игнорирует системные ошибки встроенных инструментов и рапортует об успехе.

**Рекомендации:**
1. До программного исправления прокси рекомендуется использовать инструмент исключительно в режиме генерации кода в чат (Chat Mode) с последующим ручным копированием.

**Итог:** 
Базовая архитектура применения правок через прокси технически работоспособна, но GigaChat-2-Max не справляется с жесткими требованиями Qwen Code к чистоте JSON-аргументов при использовании Tool Calling. Проблема решается доработкой прокси-сервера.
